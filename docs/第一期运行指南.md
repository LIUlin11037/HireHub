# HireHub 第一期运行指南

> 目的：在继续铺 6 个服务之前，先验证「网关 → Nacos → auth」这条最小链路能否跑通。
> 这一步过了，说明 D-03 求新路线的依赖与配置没问题，后面加服务才有意义。

## 0. 前置

- JDK 17+（`JAVA_HOME` 指向 JDK 17 或 21 均可）
- Docker 已启动

## 1. 启动中间件

```bash
cd docker
docker compose up -d
docker compose ps        # 确认 mysql / redis / nacos 三个容器 Up
```

**验证 Nacos 3.0**（注意：控制台端口是 **8080**，不是 8848）：

- 浏览器打开 `http://localhost:8080`（Nacos 控制台）
- 默认账号 `nacos` / `nacos`

> ⚠️ 若控制台打不开，先看 `docker logs hirehub-nacos`——Nacos 3.0 较新，若镜像或端口有出入，把日志贴给我。

## 2. 初始化数据库

```bash
mysql -uroot -proot < sql/init-databases.sql      # 建 7 个库
mysql -uroot -proot hirehub_auth < sql/auth-schema.sql  # auth 表 + 种子角色
```

## 3. 启动服务（IDE 里各起一个）

顺序无所谓，但建议先 auth 后 gateway：

1. `hirehub-auth` → `AuthApplication`（端口 9001）
2. `hirehub-gateway` → `GatewayApplication`（端口 9000）

**验证注册**：Nacos 控制台 → 服务列表，应看到 `hirehub-auth` 和 `hirehub-gateway` 两个服务。

## 4. 验证最小链路（走网关 9000）

```bash
# ① 注册（白名单，无需 token）
curl -X POST http://localhost:9000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"123456","phone":"13800138000"}'

# ② 登录（拿到 accessToken）
curl -X POST http://localhost:9000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"123456"}'

# ③ 查当前用户（需带 token；网关校验 JWT 后注入 X-User-Id）
curl http://localhost:9000/api/auth/me \
  -H "Authorization: Bearer <上一步的 accessToken>"

# ④ 不带 token 访问受保护接口 → 应返回 401
curl http://localhost:9000/api/auth/me
```

**通过标准**：

| 步骤 | 预期 |
|---|---|
| ① 注册 | `{"code":0,...}` |
| ② 登录 | `{"code":0,"data":{"accessToken":"..."}}` |
| ③ /me | 返回用户信息，不含 password |
| ④ 无 token | HTTP 401 + `{"code":20001,...}` |

## 5. 常见问题排查顺序

1. **服务起不来 / 编译失败** → 把 `mvn compile` 的错误贴给我（我在沙箱里跑不了 maven，编译错误只能你这边回传）
2. **Nacos 注册不上** → 检查 `spring.cloud.nacos.discovery.server-addr` 是否为 `localhost:8848`；若服务跑在容器里则要改成宿主机可达 IP
3. **网关 404** → 确认路由 `lb://hirehub-auth` 与 auth 的 `spring.application.name` 一致
4. **/me 返回 401 且带了 token** → 确认 auth 与 gateway 的 `hirehub.jwt.secret` 一致（默认值相同，若你改了环境变量要两边一起改）

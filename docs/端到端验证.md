## 角色

- **alice** = 求职者
- **bob** = HR
- **admin** = 平台管理员

所有请求走网关 `http://localhost:9000`。`{TOKEN}` 为各角色登录返回的 accessToken。

## ① 求职者 alice：注册 / 实名 / 建简历

```bash
# 注册
curl -X POST http://localhost:9000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"123456ab","phone":"13800000001"}'

# 登录 → 记下 accessToken
curl -X POST http://localhost:9000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"123456ab"}'

# 实名（校验位真算法，随便编的号会被拒）
curl -X POST http://localhost:9000/api/auth/real-name \
  -H "Authorization: Bearer {ALICE_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"realName":"李小明","idCard":"110101199003078515"}'

# 建简历 → 记下 resumeId
curl -X POST http://localhost:9000/api/resume \
  -H "Authorization: Bearer {ALICE_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"name":"李小明","phone":"13800000001","expectCity":"杭州","expectPosition":"Java","expectSalaryMin":20000,"expectSalaryMax":35000}'
```

## ⑥ HR bob：查看投递 → 面试 → Offer

```bash

  -H "Authorization: Bearer {BOB_TOKEN}" \
  -H "X-Company-Id: {COMPANY_ID}"

# 发起面试邀约
curl -X POST http://localhost:9000/api/interview \
  -H "Authorization: Bearer {BOB_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"deliveryId":{DELIVERY_ID},"interviewTime":"2026-01-15T10:00:00","interviewType":"线上","interviewerName":"王大壮"}'

  -H "Authorization: Bearer {BOB_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"event":"SEND_OFFER"}'
```


## ⑧ 企业认证复核与岗位联动下线（三期 Q-08）

> 场景：企业认证时是"存续"，之后在工商侧**注销/吊销**了。平台必须撤销它的认证，
> 并把它的在招职位一并下线 —— 否则等于用平台信用给一个已不存在的主体背书，职位还在收投递。
>
> ⚠️ **夹具为什么要改库**：Mock 核验判定"注销"的**依据是企业名**（以 `-REVOKED` 结尾或含「已注销」），
> 而提交认证会走同一个核验器 —— 所以**没法**用这样的名字走完"提交 → 管理员通过"。
> 项目也没有改名接口。故先正常认证、发职位，再直接改库把名字改成已注销：
> 这改的是**外部世界的事实**（"认证之后它注销了"），不是绕过被测逻辑。

```bash
# 0) 前置：bob 的企业已认证通过（见 ③），且已发一个在线职位（见 ④）

# 1) 把企业名改成已注销（模拟工商侧状态变化）
#    verify_time 置为最旧，确保它落在本轮复核批次内
docker exec hirehub-mysql mysql -uroot -proot -D hirehub_company -e \
  "UPDATE company SET name=CONCAT(name,'-REVOKED'), verify_time='2000-01-01 00:00:00' WHERE id={COMPANY_ID}"

# 2) 管理员手工触发一轮复核（正式路径是每天 03:00 的定时任务）
curl -X POST http://localhost:9000/api/company/admin/recheck \
  -H "Authorization: Bearer {ADMIN_TOKEN}"
# → {"code":0,"data":1}   本轮撤销 1 家

# 3) 认证已撤销
curl http://localhost:9000/api/company/{COMPANY_ID} -H "Authorization: Bearer {BOB_TOKEN}"
# → verifyStatus = 3，verifyRemark 含「定期复核：企业已注销」

# 4) 岗位被联动下线（主路径 = MQ 事件）
curl http://localhost:9000/api/job/{JOB_ID} -H "Authorization: Bearer {BOB_TOKEN}"
# → status = 2，offline_reason 非空

# 5) 该职位已从搜索里消失
curl "http://localhost:9000/api/job/search?keyword={JOB_TITLE}" \
  -H "Authorization: Bearer {ALICE_TOKEN}"
# → 结果里不再有 {JOB_ID}
```

**兜底对账**（模拟"MQ 事件丢了"：认证已失效但职位仍在线）

```bash
# 直接改库制造"事件丢失"状态：认证非通过，但职位还是 status=1
docker exec hirehub-mysql mysql -uroot -proot -D hirehub_company -e \
  "UPDATE company SET verify_status=3 WHERE id={COMPANY_ID}"

curl -X POST http://localhost:9000/api/job/admin/reconcile-company-status \
  -H "Authorization: Bearer {ADMIN_TOKEN}"
# → {"code":0,"data":>=1}，随后该职位 status=2
```

**通过标准（⑧）**：

| 断言 | 预期 |
|---|---|
| 复核后企业认证状态 | `verifyStatus=3`，备注含「已注销」 |
| 复核后职位状态 | `status=2` 且有 `offline_reason` |
| 职位是否还能被搜到 | 搜不到 |
| **MQ 主路径真的走通** | `hirehub_job.mq_consume_log` 出现 `consumer='job-company-revoke'` 的行 |
| **存续企业不受影响** | 同批的存续企业仍 `verifyStatus=1`、职位仍在线（保守优先） |
| 幂等 | 再触发一次复核/对账 → 返回 0 |
| 鉴权 | 非 `PLATFORM_ADMIN` → 403 / `20003` |
| 审计 | `sys_operation_log` 含 `COMPANY_RECHECK` / `COMPANY_RECONCILE`，`traceId` 非空 |

## 通过标准

| 环节 | 预期 |
|---|---|
| ① 注册/登录 | `code=0`，登录返回 accessToken |
| ① 实名 | 校验位真算法通过；随便编的身份证号被拒 |
| ② 建企业 | 返回 companyId，创建者成为 OWNER |
| ③ 审核 | admin 通过后 verifyStatus=1 |
| ④ 上线 | 三重校验通过（若跳过实名/未认证则被拦） |
| ⑤ 投递 | 返回 deliveryId；重复投递幂等返回同一 ID |
| ⑥ 面试→Offer | 状态机 PENDING→…→INTERVIEW→OFFER 正常流转 |
| ⑦ 拦截 | 非法事件 400、越权事件 403 |
| ⑧ 复核联动 | 认证 → 3、职位 → 2 且搜不到；存续企业不受影响；MQ 路径有消费记录 |

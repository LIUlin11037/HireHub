## 三、本轮修掉的 3 个真实缺陷

### 1. 编译期缺 `-parameters` → 所有带路径变量/参数的接口 500（最严重）

**现象**：`GET /api/company/1`、`GET /api/resume/2`、`POST /api/job/{id}/publish`、`/internal/**`
全部返回 `code=10002 系统繁忙`（实际是 HTTP 200 + 兜底异常），共 28 处。

**根因**：项目没有继承 `spring-boot-starter-parent`，`maven-compiler-plugin` 的
`<parameters>true</parameters>` 不会自动生效。而 Spring Framework 6.1 移除了
`LocalVariableTableParameterNameDiscoverer`，`@PathVariable Long id` 这类**没写显式名字**的
注解只能靠编译期保留的参数名解析，缺了就抛
`Name for argument of type [...] not specified`。

**修复**：根 `pom.xml` 显式声明 `maven-compiler-plugin` 并开启 `-parameters`。

### 2. `mvn package` 出的 jar 不能 `java -jar` 启动

**现象**：`hirehub-auth-1.0.0.jar 中没有主清单属性`。

**根因**：同样因为没继承 parent，`spring-boot-maven-plugin` 的 `repackage` 不会自动绑定到
`package` 阶段（各模块只声明了插件，没声明 execution）。

**修复**：在根 `pom.xml` 的 `pluginManagement` 里给该插件补上 `repackage` execution。

### 3. 业务异常被当成「系统繁忙」，且状态码全是 200

**现象**：「非法状态迁移」「企业未通过认证」「用户名已存在」等业务错误统一返回
`code=10002 系统繁忙`，HTTP 状态一律 200，文档要求的 400/403 无法体现。

**根因**：`BusinessException(String)` 默认码取的是 `SYSTEM_ERROR(10002)`；
`GlobalExceptionHandler` 没有把错误码映射到 HTTP 状态，`@Valid` 校验失败也被兜底成 10002。

**修复**：
- `ResultCode` 增加 `BUSINESS_ERROR(30001)`，`BusinessException(String)` 默认用它；
- `GlobalExceptionHandler` 按错误码映射 HTTP 状态（400/403/404/401/500），
  并单独处理 `@Valid` 失败、Spring 客户端异常（走 `ErrorResponse` 取状态码）。

> 注意：`hirehub-common` 同时被 WebFlux 网关和 MVC 服务复用，**不能**引 `jakarta.servlet`。
> 所以缺请求头这类是借 `org.springframework.web.ErrorResponse` 拿状态码，而不是
> `@ExceptionHandler(MissingRequestHeaderException.class)`。

### 附带：Lombok 注解处理器显式声明

第一次改完 `pom.xml` 后 `mvn package` 报一片「找不到符号 getCode()」——根因是上面第 1 条改动让
`hirehub-common` 引入了 `jakarta.servlet` 依赖导致编译中断、Lombok 未生效。已通过去掉该依赖解决；
同时顺手把 Lombok 写进 `annotationProcessorPaths` 并关闭增量编译，避免同类隐式行为再咬人。

## 四、复跑方式

```powershell
# 1) 干净构建 + 重启 8 个服务（日志落 logs/）
.\scripts\rebuild-and-restart.ps1

# 2) 按文档原值跑（alice / bob / admin）
.\scripts\e2e-verify.ps1

# 3) 全新身份 + 全新企业从零跑（-Fresh 会自动生成用户名与合法信用代码）
.\scripts\e2e-verify.ps1 -Fresh
```

脚本说明：
- `scripts/e2e-lib.ps1` — HTTP 调用封装（用 `HttpWebRequest`，因为 PowerShell 5.1 的
  `Invoke-WebRequest` 读不到 4xx/5xx 的响应体）+ 断言/汇总
- `scripts/e2e-verify.ps1` — 全流程用例（含 8 个负面用例）
- `scripts/rebuild-and-restart.ps1` — `mvn clean package` + 停旧进程 + 按端口 9000-9007 起新进程

> PowerShell 5.1 读 `.ps1` 依赖 BOM；脚本文件必须存成 **UTF-8 with BOM**，否则中文注释乱码会导致解析报错。

## 五、分期口径与遗留

**本轮验证 = 第一期验收范围**，即 `docs/端到端验证.md` 的 ①–⑧，已全绿。
以下接口**不属于**第一期验收范围，本轮未执行（不是"已知有问题"，是"未在验收范围内"）：

| 接口 | 归属 |
|---|---|
| `GET /api/interview/mine`、`confirm` / `reject` / `cancel` / `reschedule` / `feedback` | 架构文档 §10 第一期清单未含 interview 服务；属后加能力 |
| `PUT /api/resume/{id}`、`GET`/`PUT /api/resume/preference` | 字面 CRUD 范围，但不在验收路径上 |
| `POST /api/job/{id}/offline`、`DELETE /api/job/{id}` | 同上 |
| `PUT /api/notification/{id}/read`、`read-all` | 二期接 RabbitMQ 才有通知生产者 |
| `POST /internal/notify` | 同上，全项目暂无调用方（属预期） |

**一处文档口径差异（仅文档，非代码问题）**：

- `docs/架构与实施文档.md` §10 第一期验收路径含「**生成邀请码 → HR 凭码加入**」；
- `docs/端到端验证.md` 未包含这一步，本轮也未执行 `POST /api/company/{id}/invite-code` 与 `POST /api/company/join`。

两份文档对第一期验收路径的定义需要对齐：要么把这步补进 `端到端验证.md` 并验证，
要么从架构文档的第一期路径里移除。

其他：

- 用例为幂等设计：用户名/信用代码重复时复用既有数据（`已存在`/`已入驻` 分支），可直接重复执行。
- `docs/端到端验证.md` ⑥ 只写了「发起面试邀约 → 发 Offer」，但投递状态机要求先到 `INTERVIEW`
  才能 `SEND_OFFER`，因此脚本里补了一步 `INVITE_INTERVIEW` 事件；建议把这一步补进文档。
